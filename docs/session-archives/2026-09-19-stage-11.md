### Stage 07 — appearance re-identification (`dd0e6d8`)

The measurement contradicted the contract. The contract proposed an auto-accept
similarity of 0.92; at 0.92 twenty-one hard-negative decoys are auto-accepted,
at 0.95 **none** are, and recall is unchanged at 1.000. The decoy band tops out
at 0.9389, so 0.95 clears it entirely.

Topology-constrained retrieval beat unconstrained on precision (0.100 → 0.160 on
hard negatives) at zero cost to recall. Restricting the search space beat raising
the threshold.

The rule that appearance can never outrank a plate match became an inequality
checked at startup rather than a comment beside the YAML.

Seven test failures along the way, all from the same cause: `Target.reference_embeddings`
validates dimension 512, and the tests used DIM=32.

### Feature backlog (`63917bb`)

`docs/FEATURE_BACKLOG.md` — the four requested capabilities that are not in the

### Stage 08 — path reconstruction (`2ef6bd5`)

The per-node inclusion bonus measured to **zero**, against the contract's
expectation of a positive value. The arithmetic: with multiplicative hop
weights, inserting a candidate of confidence *c* between neighbours *a* and *b*
changes the score by `c(a+b) − ab + bonus`, which is exactly zero at
`c = ab/(a+b)` — 0.45 for two 0.9 neighbours, which is precisely stage 07's
visual-only ceiling. **The bonus is the whole of the margin by which a
visual-only candidate gets chained in.** At 0.05 the engine strung decoys
through the adversarial route until no competing account survived, and reported
it as unambiguous — confidently wrong.

A 700 km/h hop appeared in a reconstructed route; fixed by making physically
impossible transitions produce no edge at all.

`ARITHMETIC_MEAN` confidence was removed: with the weakest-link cap applied it
cannot produce a different number, so it was configuration with no reachable
behaviour.

### Stage 09 — time synchronization (`32be503`)

The offset solver was wrong **twice**, and both failures are worth remembering.

**Jacobi relaxation oscillates on a chain of cameras.** A path graph is
bipartite, and Jacobi on a bipartite Laplacian does not converge — it returned a
stable-looking 36.7 s where 12 s was correct. Replaced with direct least-squares.

**Iterative reweighting failed on the case it existed for.** A three-hour
outlier skewed the seed fit so far that the *good* passes looked like outliers,
and the estimate came back thirty times too large. Robustness that depends on
the first guess being roughly right is not robustness. Replaced with per-link
medians, which one outlier cannot move however extreme.

The drift detector, run against real generated data, flagged **every camera in
the network**. Two guards were added: a rate needs an hour of observation span,
and a bias must exceed its own scatter.

A test whose scatter aligned with the leg count (`index % 3`) made the system
artificially consistent and drove residuals to zero; fixed with a coprime period,
`(index * 37) % 61 - 30`.

### Stage 10 — video ingestion (`61ba055`)

**The rotation inverse was off by one** — exact at one corner of the frame and
off by the full width at the other, which reads as a flaky detector rather than
as arithmetic. `np.rot90(k=1)` maps source `(x, y)` to `(y, width − 1 − x)`.

**FFmpeg identifies almost anything.** A file of ASCII text opened as `bintext`,
640×64 at 25 fps, and yielded a junk frame. A decoder agreeing to open something
is not evidence that it is a video. PyAV now identifies and OpenCV decodes.

Abandoning a frame generator leaked the decoder: only the file source released
on iteration end, so breaking out of a loop held the handle until the collector
ran. Closing on iteration end became the default.

`time.sleep` returns early on Windows, so the stall test was rewritten to measure
against an unstalled run rather than the wall clock.

### 3.2 Configuration

Thirteen new required thresholds in `config/thresholds.yaml`, under a heading
that opens **NOT MEASURED** in capitals — see section 4.

Two new cross-field validators on `ThresholdSettings`:

- aspect-ratio bounds must be ordered, because an inverted window rejects every
  detection and produces a camera that silently sees nothing;
- the four best-frame weights must sum to 1.0, because each criterion scores in
  `[0, 1]` and any other sum puts the composite outside that range.

A new `DetectionSettings` section in `config.py` for execution knobs — backend,
batch size, edge policy, retention cap, thumbnail shape, long-track split. The
split from `VisionSettings` is deliberate: that section describes the *models*,
this one describes what this deployment does with them.

Adding thirteen required fields broke two existing config tests that enumerated
every threshold inline. Rather than extend the lists, `tests/unit/test_config.py`
gained a `threshold_kwargs(**overrides)` builder, so the next stage to add a
threshold changes one dictionary instead of every cross-field test.

### 3.4 Decisions taken while writing, with the rejected alternative

**Greedy matching vs optimal assignment.** Greedy takes the single cheapest pair
first and leaves the other track whatever remains, which can be the wrong
detection even when a different pairing is better overall — an identity swap,
happening exactly when two vehicles are close together. Jonker-Volgenant was
written out rather than adding SciPy for one function. The unit tests include
the matrix where greedy is provably wrong:

```
[[1, 2],        greedy: (0,0)=1 then forced (1,1)=100  -> 101
 [2, 100]]      optimal: (0,1)=2 and (1,0)=2           ->   4
```

**Forbidden pairs cost 1e6, not infinity.** The solver subtracts potentials from
costs, and an infinity there propagates into every row it touches. A cost far
above any real one has the same effect on the solution and none of the
arithmetic hazards.

**Sighting confidence: median, not mean or maximum.** A track's first and last
frames are legitimately uncertain — the vehicle is half out of frame — and drag
a mean down without saying anything about whether a vehicle passed. A maximum
lets one lucky frame promote a track of marginal detections to near-certainty.

**Sighting timestamp: the midpoint frame.** Dating from the first frame places
every vehicle systematically early, by an amount that varies with the camera's
field of view. That bias survives every local test and quietly corrupts
travel-time plausibility across the whole topology.

**The thumbnail may come from a different frame than the timestamp.** The
sighting is dated and boxed from the midpoint; the image is cropped from the
highest-ranked frame, because that image exists to be *read*. The tension is
real and is documented rather than resolved, because the prompt asks for exactly
this and the alternative — a blurrier thumbnail — is worse.

**Age counts tracker updates, not source frame indices.** The tracker is fed
sampled frames, so consecutive updates can be six source frames apart. Counting
source indices would make the occlusion allowance depend on the sampling rate.

**Memory: a sliding top-K, not a full-track ranking.** A frame evicted early
cannot come back even if every later frame turns out worse. That is the price of
a fixed memory bound; the alternative is holding every crop of a ten-minute
track to be sure.

**Crops are owned copies.** A decoder hands out a view into a buffer it reuses,
so a crop kept as a view would change underneath the track — producing a
thumbnail of a vehicle from a later frame, a symptom that reads as a cropping
bug rather than an ownership one.

**Detection permits a zero-area box.** That is what a model reports when it has
latched onto nothing, and rejecting it in the constructor would move the failure
out of the filter that exists to count it and into an exception halfway through
a batch.

**A fixture detector raises on an unrecorded source.** Returning nothing would be
indistinguishable from an empty road, and a test asserting "no false positives"
would pass triumphantly against nothing at all.

**The `fake` backend from configuration is scripted with nothing.** A fake that
invented detections from config would be placeholder logic, which the contract
forbids. Tests construct `FakeDetector` directly with the script they mean.

### 3.7 Failures that were findings, not mistakes

These are the four that taught something, and all four are now in
[`../DECISIONS.md`](../DECISIONS.md) and [`../DETECTION.md`](../DETECTION.md).

**A negative box coordinate out of the rotation inverse.** The end-to-end test
pushed `sample_clean.mp4` through a 90° rotation plus a resize and got
`bbox=[-1, 16, 11, 32]`, which `Detection` rejected. This is *not* the stage 10
off-by-one, which was a genuine bug and is fixed. It is the residue of a
convention: stage 10's mapping works in pixel **centres**, where the inverse of a
90° rotation is `width − 1 − x`; box coordinates are **half-open**, so a box edge
legitimately sits at `x = width`, and mapping that edge back gives −1.

Fixed in `Detection.in_source_coordinates` with a one-pixel clamp and a docstring
explaining precisely why one pixel and not more — anything larger is a genuine
mapping fault and is still left to fail against the non-negativity check.

**`sample_clean.mp4` contains two vehicle passes, not one.** The e2e test
asserted one track and got two: frames 0–17 with 18 hits, then frames 18–19 with
2. Reading the generator explained it — the bar is drawn at `(index * 3) % 52`,
so on frame 18 it wraps from the right edge back to the left. The tracker called
it a second vehicle and was **right** to: a real object cannot cross a frame in
one frame interval, and a tracker that accepted the teleport would be the one
that merges two vehicles into a single trajectory. The test now asserts two
passes and documents the wrap.

**`SyntheticVideoSource(moving_rectangle=False)` is not a static scene.** The
motion-prefilter test asserted a skip ratio above 0.5 and got **0.095**. The
first reading was "the gate is broken". It was not: that source shifts its whole
background by two or three greyscale levels every frame by design, which is
above the gate's default sensitivity of 2.0, so a gate watching it correctly
reports motion. "A street camera at night sees the same empty road for hours"
means *identical frames*, so the test now feeds identical frames and the gate
skips 97%.

**Millisecond truncation vs microsecond decoding.** A sighting's timestamp came
back as `...594000` against the frame's `...594467`. The domain model truncates
to milliseconds at validation so a round trip through storage is lossless
(stage 02); a decoder reports microseconds. The assertion was wrong, not the
code — comparisons must be made at the precision the record actually keeps.

**Fixture images at 126 KB each.** The first `scene_image()` added seeded sensor
noise, which is the honest way to imitate a camera and also makes a PNG
incompressible. Three images came to 375 KB. Nothing that uses them exercises a
noise model, so the noise was removed and the same three images are now
471–1008 bytes.

15 test modules. The division of labour the prompt asks for, and which was
followed: **tracking logic is tested exhaustively against the scripted fake**,

non-empty image; the assignment solver pairs each row and column at most once.

## 4. The honest limitation of this stage

**Nothing in stage 11 is calibrated, and the configuration says so in capitals.**

Every earlier stage swept its thresholds against stage 05's ground truth, and
three of those sweeps contradicted the contract's priors. Stage 11 could not
sweep anything: the only detector available in this environment is a synthetic
blob-finder, and sweeping the minimum box area or the association IoU against it
would calibrate the shape of a drawn bar.

So the stage 11 block of `thresholds.yaml` opens with `NOT MEASURED`, each value
carries the reasoning that produced it, and **stage 13 or 20 owns re-deriving
them against a real detector on real footage.**

One value is structurally argued rather than guessed: the four best-frame
weights must sum to 1.0, because each criterion scores in `[0, 1]`. That is
enforced at startup.
